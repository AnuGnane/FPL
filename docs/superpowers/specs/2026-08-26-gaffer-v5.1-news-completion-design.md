# Gaffer v5.1 "News Completion" — Design

Approved 2026-08-26 ("Lets do 1 and 2 together"). A short pass finishing the
two halves v5 §12 recorded as dormant: the FFS predicted-lineups parse and
the Transfermarkt injury-curve calibration. Both designs are grounded in
live-page probes taken today (the v5 lesson: never guess a page shape).

## 1. FFS predicted line-ups — real page shape (`data/news/lineups.py`)

Probe findings (fantasyfootballscout.co.uk/team-news, 625 KB, 20 clubs):

- Each club is an `<h2>ClubName</h2>` section followed by a
  `scout-picks-pitch formation formation-*` div holding `ul.players` /
  `row-N` lists.
- Each predicted-XI `<li>` carries `title="Surname (First)"` **and** an
  `<img src=".../photos/players/110x140/{code}.png">` — that `{code}` is
  the FPL player code. The XI therefore joins **by code, no name matching
  at all**.
- Below the pitch: `Out:`, `Doubts:` and `Banned:` lists with player names
  as text — matched by name, scoped to the section's club (the `<h2>`
  resolves through `club_code_map`/aliases; FFS uses long names like
  "Brighton and Hove Albion").

Hint mapping (conservative — only explicit statuses get hints):
XI → 1.0 (a no-op ceiling by design), Doubts → 0.25, Out/Banned → 0.0.
Players on none of the lists stay unhinted — a mere omission from the
predicted XI is NOT treated as evidence this cycle; revisit with shadow-log
data. Parse failure anywhere degrades to the empty frame as today.

Output shape, coverage floor, GW1-only semantics, and the `[news]` config
are unchanged. The fixture `tests/data/news/ffs_lineups.html` is rewritten
to the real shape (title-attribute names, photo-code URLs, Out/Doubts
lists); the code-join, the club-scoped name match, and the no-op-XI rail
each get a test.

## 2. Transfermarkt per-player calibration (`data/news/transfermarkt.py`)

Probe findings: the v5 club-level history URL does not exist, but

- `/{club-slug}/kader/verein/{id}/saison_id/{year}` lists the squad with
  `href="/{player-slug}/profil/spieler/{pid}"` links (~30 players/club);
- `/{player-slug}/verletzungen/spieler/{pid}` serves an `items` table with
  columns `Season, Injury, from, until, Days, Games missed` — **exactly
  the shape `parse_injury_spells` already parses** (the committed fixture
  was right; only the URL scheme was wrong).

Rework: `squad_player_ids(club_slug, club_id, season_year)` (parse the
squad page) and `fetch_player_spells(player_slug, player_id)` (per-player
page through the existing parser, cached permanently per player);
`run_calibration` walks clubs → players → spells (~20 + ~600 requests,
50 ms pacing, every failure skips-and-counts). `fetch_club_spells` and
`club_url` are deleted — they point at a page that does not exist. The
CLI, fitter (`fit_curves`), validator (`write_curves`) and asset loader
are untouched.

The calibration is then RUN (the pass's one large network step, cached
under `data/raw/news/transfermarkt/`) and the validated
`src/gaffer/assets/injury_return_curves.json` is **committed** — lighting
up the typed-decay chain shipped in v5. §12 records spells ingested,
curves fitted per type, and the pooled curve.

## 3. Verification

Suite green throughout; no network in tests (fixtures for the squad page
and the new FFS shape). Live smokes, orchestrator-run: (a) a `gaffer
advise` run must parse real line-ups (rows > 0, hints in the shadow log's
moved set where genuine); (b) `load_injury_curves()` returns the committed
asset and `apply_availability` uses a typed curve end-to-end. v5's
degradation rails must still pass — the news layer with everything down
remains byte-identical to flags-only.

## 4. Not in this pass

Omission-from-XI as a bench signal (needs shadow evidence); any second
lineups provider; automating the calibration on a schedule; the deferred
nits ledger.

## 5. Outcome

Shipped 2026-08-26. Suite 1207 Python; both dormant halves are live.

**FFS parser** (`b4ae072`): the probe's shape held with three live
corrections — `row-N` is the pitch and `class="players"` the absence
lists (inverted from §1's reading), the site emits a `</uL>` typo, and an
editorial **"Scout Picks" widget uses byte-identical pitch markup** whose
eleven real photo codes would have joined as predicted starters. Guards:
a section whose `<h2>` is no club we carry contributes nothing, and a
photo code that disagrees with its heading's club is dropped. Code-joined
XI rows never touch the name matcher (and leave its candidate pool); the
coverage floor guards only the name-matched absences. Live smoke: 298
rows → 283 in scope (15 = the widget) → **277 hints (220 XI, 44 out, 13
doubts)**, name matching 57/63 (90%). In production advise: 77 injuries +
277 hints, 614 shadow rows, 22 players moved, captain unchanged.

**Transfermarkt calibration** (`2c1984f`, asset `9e41094`): squad-page →
per-player discovery worked in one clean sweep — **3381 spells from 504
players, 20/20 clubs, zero club failures** (73 players skipped: empty
histories, indistinguishable from dead pages by design). **16 typed
curves committed** (achilles at 24 spells fell under the 30-spell floor
into pooled, as designed). Pooled: [0, .199, .410, .534, .622, .691,
.737, .776, .805]. The spread the flat 0.7 hid: knock [0, .358, .665,
.800…] vs hamstring [0, .047, .123, .274…]. `load_injury_curves()` now
returns the committed asset and the typed decay chain shipped in v5 is
live end-to-end.

**Rail correction, deliberate**: the two "no asset ⇒ v4 geometric" rails
passed `curves=None`, which means *load the shipped asset* — they only
pinned the fallback because the file happened not to exist. They now
monkeypatch `load_injury_curves` to `None`, pinning the actual rail (a
clone without the file) rather than an accident of the tree.

Problem. "What does the user see for GW7?" is answered across four modules: the objective week is a bare dict, serve_rung hands back a bag of thirteen keys, Advice is splatted from it field by field, and the plan router re-parses the JSON with its own coercers and re-runs the bank because the artifact carries no money.

Solution. One ServedPlan value object built in advise, written whole, and read back by one loader that every router, the CLI, the brief and the digest call; artifacts owns every path and the enumeration of gameweeks.

  • locality: week shape defined once, not eight times
  • leverage: one loader, twelve call sites
  • plan router's bank arithmetic deleted
  • one round-trip test replaces the coercer tests
  • path knowledge leaves meta.py and tracking.py
  • serve_rung's interface shrinks to one return type
Touches advise.py and ladder.py, both orchestrator-only under CLAUDE.md, and moves the v16 source-order pins in tests/test_v16_restraint.py; the plan for this cycle records that ruling.

Problem. The weekly run is defined inside an HTTP router, imported from there by the job registry, and re-assembled by hand in the CLI, which is why the CLI and the Thursday plist produce advice with no brief.

Problem. Rendering one hub in a test means faking eight GET endpoints and a POST, four hubs each fetch the latest advice for themselves, and a card that starts work picks between two job hooks by a server detail.

Solution. A shared loader with one in-flight request per endpoint, the row assembly as a pure function, and one job hook that chooses its transport internally.

  • locality: row bugs tested in squadRows
  • capLine prop-drilling deleted

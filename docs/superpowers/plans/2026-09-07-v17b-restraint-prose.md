# v17b — restraint narrated once, on the server: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Spec: `docs/superpowers/specs/2026-09-07-v17b-restraint-prose-design.md` (read it first; every section number below is the spec's). Branch `v17b-restraint-prose`, off `main` at `2290a93`.

**Goal:** every rung the server serves carries `label`, every step `line`, the restraint block `label`, `hit_cost` and `line`, the objective block `line`; the CLI, the brief, MovesCard and LadderCard render those strings and compose nothing.

**Architecture:** `src/gaffer/ladder.py` becomes the one author of restraint prose, its four helpers private. `build_ladder` labels rungs and lines steps; `load_ladder` backfills a v16 file; `serve_rung` writes the served block's prose. Consumers read fields. A cross-language rail (Python writes a fixture of served strings, vitest renders it) proves the four surfaces agree.

**Tech Stack:** Python 3 / pydantic / pytest; React 18 + TS + vitest; `npm run types` for the generated types.

**Rules that apply to every task:** stage explicit paths only; commit subject `<type>(v17b): …`; never touch `config.toml`; the orchestrator-only files are `src/gaffer/advise.py`, `tests/test_v16_restraint.py`, every `tests/test_v*_degradation.py`, `tests/test_advise.py` — an implementer who finds it needs one stops and reports. Do not edit `frontend/src/types.generated.ts` or `schemas.json` by hand.
